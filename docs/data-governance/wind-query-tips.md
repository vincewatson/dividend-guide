## Wind 拉取经验清单（节约调用次数）

**A. 拉取前必查 3 件事**：① 先读现有 JSON 确认覆盖到哪（增量起点）；② 只拉缺口，全新数据才全量；③ 判断配额状态，刚大量用过优先 iFind 补数。

**B. 拉取中 4 技巧**：① 批量查询（BATCH_SIZE=3 一批查多个）；② 日期分段（**单次返回上限约 100 行**，按段拉取宁多勿截断；REITs 日频按每段 135 日历日）；③ 按需拉取（只拉页面展示字段）；④ 增量合并去重。

**C. 出错 3 纪律**：① `QUOTA_ERROR` 禁止原样重试，改备用源或等刷新；② QPS 限流等 3-5 秒可原样重试一次；③ 失败不破坏（保留旧数据）。

**D. 落地优化参考**：sync_div_history 增量（49 指数 ~588→~10 次）；sync_money_fund 只更新头部；sync_yuebao_history 按月分段去重；REITs 日频 58 只×10 段=580 次分两批断点续传（reits_daily_fetch.py，进度落盘可续传）。

**E. 2026-08-16 实测补充**：
- **divDate 查询措辞（2026-09-13 复测修订）**：措辞会随 Wind 语义漂移，**固定单一措辞不可靠**。
  - 当前主措辞 = **「{code} 最近分红情况」**（返回含「基金红利发放日」列的表，含最新发放日；实测 004597.OF → 2026-08-28 正确）。
  - 旧措辞「{code} 最近分红发放日期」**本轮已失效**（返回"没找到数据"；08-16 时曾最稳定），仅作兜底。
  - sync_fund_divdate.py 已改为**多措辞依次兜底**（最近分红情况 → 最近分红发放日期 → 基金分红 分红发放日），首个返回发放日者即用。
  - 验收看**覆盖率**（fund ≥25/26、etf ≥14/15、cnEtf ≥50）：措辞失效会整体拉低覆盖率。
  - 教训（08-16 曾致 fund 5 + etf 6 缺失）：**任何措辞都可能某天失效**，故需多措辞 + 覆盖率硬门槛双保险。
- **dailyChange 全量重拉可能漏指数**（批量截断）：08-16 曾致 932584.CSI 停在 08-11；运行后核对更新数与指数总数（48/49），check_data 已加「全覆盖」检查拦截（见 `check_data.py`「dailyChange 全覆盖」项）。
- **Wind 配额用尽**：立即停止批量拉取，把断点写入 `changelog/` 当月文件（当前进度/缺失项/恢复步骤），配额刷新后从断点继续（所有脚本为增量逻辑，安全）。
- **基金/ETF 查询稳定搭档**：`get_fund_financials` 措辞 `{code} 最近分红发放日期`（保留 .OF 后缀）；港股 .HK 跳过保留原值。
- **单次查询字段数 ≤7 个**：超过则 Wind 返回"没找到数据"（08-16 实测，12 字段查询全部落空）；拆两次查询合并。
- **批量查询需限速**：连续同类查询（如"跟踪X的基金数量"）高频触发 Wind 限流返回空表 → 批次间 sleep ≥10 秒；失败批次可重跑（增量逻辑安全）。
- **列名不稳定**：「跟踪X的基金数量」有时带"指数"二字（跟踪指数X）→ 解析用正则 `^跟踪(指数)?` 兼容。
- **ETF 上市临时 N 前缀**：交易所对刚上市产品简称加"N"（new），上市数日后摘除；判断标准=网站简称带 N 而 Wind 证券简称不带 N → 摘除（fix_n_prefix）；摘除后 Excel 快照残留 N 不恢复（sync_excel 保护）。

**F. 2026-08-29 补充（工具契约变更）**：
- **EDB 取数工具已更名**：`economic_data.natural_language_get_edb_data` 已下线（ROUTE_ERROR）；现用 `search_economic_indicator`（找指标/确认代码）+ `query_economic_indicator_data`（取时序，**beginDate/endDate 必填，格式 yyyy-MM-dd，或 observation 近N期，勿把日期塞进 question**）。返回结构为 `metrics` 数组（`meta`/`date[]`/`value[]`，日期为 yyyymmdd 紧凑格式需归一化）。sync_asset_macro.py 已于 08-29 适配。
- **`query_economic_indicator_data` 会同时返回日频/月频等多条同名指标**（如 LPR 5 年日/月各一条），解析按 meta.name 匹配取第一条即可，值一致。

**G. 2026-09-13 实测补充（列错位 / 瞬时失败 / 措辞漂移）**：
- **指数股息率查询「按月列出」≠ 日频**：「最近36个月…按月列出」返回 **5 列**（含"发布日期"）且为**月末**数据（列顺序与日频不同：`[代码,简称,发布日期,股息率,日期]`）→ 按固定索引解析会错位（row[3] 为数值）。**日频查询才返回 4 列** `[代码,简称,股息率,日期]`。解析一律**按列名**（`'股息率' in name` / `name=='日期'`），不要按索引。
- **fix_laggard_indexes 已修复**：原按月措辞既会错位报错、又会把日频 divHistory 覆盖成月频（违反"绝不删除旧数据"）；改为日频查询 + **合并**（只补最后日期之后缺口）+ 原子写入。
- **瞬时失败**：单个 Wind 子查询可能偶发返回空（同一次运行内，3年期储蓄国债成功、5年期储蓄国债为空；yuebao 某段为空）。**必须重试 + 合并**（sync_yuebao_history 已加重试 3 次 + 与现有文件合并兜底），否则整体重写会静默丢历史。
- **列名/措辞均会漂移**：结论同上——解析按列名、查询多措辞兜底、以覆盖率/连续性做验收，而非假定某个固定格式或措辞永久有效。

- **修复后**：3 年期 154 点 / 5 年期 258 点，均到 **2026-09-18**（周五）。

**I. 2026-09-19 实测补充（多代码批量契约 + 运行耗时/观感）**：
- **多代码分隔符是"分工具而定"的，且空格分隔会静默丢码**（本条最贵，务必记牢）：
  - `index_data.get_index_price_indicators`：**逗号**分隔有效（`932584.CSI,932422.CSI` → 2 行，列 `[最新交易日,涨跌幅,Wind代码]`）；**空格分隔只返回第一个代码**，其余静默丢失——不会报错，最易踩坑。
  - `index_data.get_index_fundamentals`：**顿号（、）**分隔有效，返回合并表并带 `Wind代码` 列。
  - 解析一律**按列名**取值（`Wind代码` / `最新交易日` / `涨跌幅`），列顺序会漂移。
- **批量有硬上限，超限整批失败**：`get_index_price_indicators` 实测 **12 只/批 → 12 行/0 缺失（OK）**；**25 只/批 → `KeyError: 'content'`（返回的是错误体、非数据表）**。当前安全口径 **≤12 只/批**，且**整批失败须回退逐只查询**（既保数据不丢，也能定位到具体哪一只异常）。
- **收益实测**：`sync_daily_change.py` 由 49 次单只调用 + 每次 `sleep(2)`（约 5 分钟）改为 5 批（12 只/批）→ **94 秒**；与生产文件逐字段比对「总数/范围/缺失」= **0 变化**，无静默丢数。
- **"像卡住了"的两个真凶（与 Wind 无关）**：① 部署/长命令用 `... 2>&1 | tail -6`，**管道会缓冲到进程结束才输出**；② `curl -s` 无超时，在被拦截的出口（如 vercel.app）上会**挂死**。已改为 `export PYTHONUNBUFFERED=1`、`curl --connect-timeout 10 --max-time 20`，并给每个 Python 步骤加 开始/结束/耗时 + 30s 心跳。
- **固定休眠是耗时主因**：`sync_wind_fields.py` 原 `sleep(10/3/2s)` 全量一趟单休眠就约 5 分钟 → 收敛为「轻查询 1s / 重查询(fundCount) 3s」（可用环境变量覆盖），保留 `call_wind` 的 3 次重试 + 6s 退避以兼容 QPS 限流。
