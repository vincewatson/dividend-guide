## 归档粒度与写法约定（2026-09-20 确立）

**背景**：`2026-09.md` 到 09-20 已达 ~50.7 KB、39 条，与 `2026-08.md` 全月的 ~52.9 KB、98 条基本相当。照此速度本月结束将明显超过上月，说明"**按月**"这一归档粒度已跟不上更新频率；同时不少条目写成了接近**逐字调试记录**（含大量实测数据），可读性与可维护性都在下降。

**结论：粒度与写法同时收紧，规则如下。**

### 归档粒度（拆分规则）

- **默认按月**建文件：`YYYY-MM.md`。
- **触发拆分**：当月文件超过 **40 KB**（约 60 条）时，**从次月起**改为**按半月**拆分：`YYYY-MM-上.md`（1–15 日）/ `YYYY-MM-下.md`（16–月末）。
- **不追溯拆分**：已达阈值的既有文件保持单文件，避免打断既有链接与引用。
- **本月的判定**：`2026-09.md` 已超阈值，但记录集中在 09-13 ~ 09-20（**均在下半月**），追溯拆分只会产出一个近乎空白的"上半月"文件，收益为负 → **2026-09 保持单文件**，新规则自 **2026-10** 起执行（若 10 月触发阈值即按半月拆）。

### 条目粒度（精简要求）

- **一条 = 一个可独立复述的变更**；不要把一次会话里的多轮微调拆成十几条，也不要把多个不相关改动塞进一条。
- **长度上限**：变更列 **≤ ~150 字**、要点列 **≤ ~120 字**；超长条目须拆分或压缩。
- **冗长细节外移**：实测数值、复现步骤、根因推导等写进 `reference/` 或 `data-governance/` 的对应文件；changelog 只保留**结论 + 验证方式**。
- **禁止逐字调试日志**：不粘贴原始输出/报错堆栈，改为"现象 → 根因 → 处置"一句话概述。
- 表格格式固定为 `| 日期 | 变更 | 验证/要点 |`；日期用 `MM-DD`（跨月文件内可省略年份）。

### 排序与修订

- 建议按**日期倒序**（最新在上）；历史既有顺序不追溯调整。
- **只增不改**：历史条目内容保持原样（仅允许修正**失效的跨文档引用**，如原章节编号改为章节名）。
