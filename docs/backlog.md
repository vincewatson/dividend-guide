- **状态**：✅ **已完成（2026-10-06，excel-exit P0+P2）**。P0 把清单/标注冻结为 `data/curation/*.json`（**列按表头名存储**）；P2 让 `build_lists.py` 8 个 builder **一律按【列名】取值**，`pd.read_excel` / 列下标路径与 `pandas`/`openpyxl` 依赖**已删除**。
- **结果**：不再有「挪列即静默错位」的隐性契约；`data-catalog.md` 对应章节改为「清单/标注来源（`data/curation/`）列结构与编辑约定」，`data-format-rules` / `update-mechanism` / `weekly-update-checklist` 同步更新。
- **验收（达成）**：parity 工具比对 P1(Excel 清单) vs P2(curation 清单) → 8 个 builder **输出 0 差异**（顺序 + 逐字段）；`check_data` ✅；`main()` 产出与改前**逐字节一致**。
- 以下为**原始立项说明**（保留追溯）：

- **原状态**：待实施（2026-09-20 立项，用户要求"列为中期改进项，本次不改代码"）。
- **现状**：`build_lists.py` 用 `pd.read_excel(path, header=None)`，**按列下标取值**（如 `r[1]` 取简称、`r[3]` 取跟踪指数代码）。文档（`data-catalog.md`「规范数据库（Wind Excel 快照）表头结构」）因此必须写死一条隐性契约：**"改表头文字不影响解析，但增删/移动列必须同步改脚本下标"**。
- **风险**：这是一条**只能靠人记住**的契约。人在 Excel 里手滑拖动一列（或 Wind 导出模板列序调整）而忘了同步改代码时，脚本会**按错位的下标静默取值**——不报错、不抛异常，直接把错误的列写进 JSON。属于"沉默的错位"，比显式报错更难发现。
- **目标**：改为**按表头名称取值**（读首行表头 → 建立 `列名 → 下标` 映射 → 按名称取），列顺序变动自动兼容；只有当**表头文字本身**被改名时才需要改脚本，并对此加断言（列名缺失即报错）。
- **收益**：消除"挪列即静默错位"的隐性契约；`data-catalog.md` 对应章节的"列顺序是硬约束"表述可随之放宽为"列名是硬约束"。
- **触发时机**：下次较大改动 `build_lists.py` 的解析逻辑时一并重构（避免为改而改）；或出现一次疑似列错位事故后**立即**上升为必修项。
- **验收**：改后跑一次完整流水线，产出 JSON 与改前**逐字段一致**；再手工交换 Excel 两列顺序，确认解析结果不变（当前实现下会错位）。
