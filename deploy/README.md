# 部署说明（本地开发模式 · 2026-10-08 起）

用户要求：一段时间内以本地调整为主（样式、页面等），**做完只给用户看本地页面，不每次都部署**。

## 规则（给 Agent）

1. **默认不部署**。`deploy/LOCAL_MODE` 存在即处于本地模式。任何改动做完后：
   - 给用户看本地页面：双击 `deploy/本地预览.command`（会在浏览器打开 `http://localhost:8090/`），或在 TRAE 里用本地预览打开同一地址；
   - 在 `deploy/待部署清单.md` **追加一行**（没有就新建，表头见下）：时间、类型（样式 / 页面 / 数据 / 脚本 / 修复）、改了什么（一句话，用户看得懂）、涉及文件。
2. **数据更新**（`auto_sync_deploy.sh`）在本地模式下照常取数、校验、刷新内嵌数据，但**跳过部署和线上验证**，并自动在清单里记一行“数据更新”。
3. **只有用户明确说“部署”时才部署**，按顺序：
   1. 读一遍 `deploy/待部署清单.md`，向用户复述本次要上线的内容；
   2. `python3 check_data.py` 全部通过（部署硬门槛）；
   3. 提交 git，运行 `bash deploy_cloudflare.sh`（或 `bash auto_sync_deploy.sh --deploy` 跑数据并部署）；
   4. 线上核对清单里的每一项；
   5. 把清单内容按条目写进 `docs/changelog/` 当月文件（留档），然后**删除 `deploy/待部署清单.md`**。
4. 退出本地模式：删除 `deploy/LOCAL_MODE`，恢复“每次更新都部署”。

## 待部署清单格式

```
# 待部署清单

| 时间 | 类型 | 内容 | 涉及文件 |
|---|---|---|---|
| 2026-10-08 15:20 | 样式 | 首页表格行距调小 | mobile.css |
```

## 注意

- 本地预览用的是简单的本地服务器：网站页面、数据、图表都能看；但 `functions/` 里的线上接口（如 studio 后台）在本地不可用，属正常。
- 本文件夹不会被部署上线（`deploy_cloudflare.sh` 已排除 `/deploy`）。
